# Findings, ordered by severity

1. **Critical — Type tests cannot handle all legal record pointers.** [Lines 408–441, 455–459](/Users/kyle/projects/oberon/agents/vision.md:408). **Unsound or underspecified rule.** `&` may produce a record pointer to a global, embedded field, or array element, but dynamic type lookup assumes a descriptor immediately before the pointed-to record. The current [runtime implementation](/Users/kyle/projects/oberon/runtime/oberon.c:75) reads `pointer[-1]`; for these pointers that is unrelated storage, even when the containing allocation is on the heap. **Example:** take `&items[1]`, pass it as `^Shape`, and evaluate `p is Circle`. **Smallest fix:** restrict dynamic record pointers to descriptor-bearing allocation roots and specify how pointer types preserve that restriction, or explicitly replace the header lookup with a representation that supports interior and foreign pointers.

2. **Critical — The heap rule does not close escape paths through parameters and subobjects.** [Lines 412–418](/Users/kyle/projects/oberon/agents/vision.md:412). **Unsound or underspecified rule.** Banning “the address of a parameter” leaves `&r.field`, `&a[i]`, and slicing a record parameter’s array field unresolved; structured value parameters and `var` parameters alias caller storage, which may remain on the caller’s stack because its procedure contains no address operation. **Example:** a callee returns `&r.field` from a record parameter supplied by a caller-local record; separately, `return r.buf[:]` must promote the containing local `r`, not merely identify `buf` as sliced. **Smallest fix:** define addressability and promotion in terms of the root storage object, prohibit escaping addresses/views into parameter-owned or parameter-aliased inline storage, and distinguish those from the separately allocated referents of pointer and slice parameters.

3. **High — Address-taking can bypass immutability.** [Lines 275–276, 340–344, 408, 499–506](/Users/kyle/projects/oberon/agents/vision.md:499). **Unsound or underspecified rule.** “Any variable, field, element” is broader than the immutable-parameter, immutable-string, and read-only-export rules, and there is no read-only pointer type to preserve those restrictions. **Example:** `var p = &s[0]` followed by `p^ := 65` would mutate a string, potentially writing static literal storage; `&Other.exportedVariable` presents the same problem for exports. **Smallest fix:** require a writable designator for ordinary address-taking and propagate read-only status through inline fields and arrays; separately state where indirection through a pointer or slice permits mutation.

4. **High — Anonymous slice types make the central examples untypeable without a compatibility rule.** [Lines 76–98, 265–267, 390–394](/Users/kyle/projects/oberon/agents/vision.md:265). **Unsound or underspecified rule.** Fresh type identity does not automatically imply incompatibility, but the document supplies no slice assignment, argument, or result compatibility exception: `Largest`’s parameter and its caller’s literal construct different slice types, as do `Grow`’s declared result and `new([]int, n)`. Existing Oberon procedure-signature matching can justify `CompareInts` as the anonymous `qsort` callback, and record-pointer extension can justify the corresponding pointer conversions; neither resolves new slices or pointers to scalars. **Example:** `proc F(xs: []int) {}` called with `[]int{1}` has no stated compatibility derivation. **Smallest fix:** distinguish type identity from value compatibility, explicitly preserve procedure-signature and record-pointer compatibility, and specify compatibility for slices and pointers to non-record types.

5. **High — Variadic C calls require more than a flag.** [Lines 783–796, 961–966](/Users/kyle/projects/oberon/agents/vision.md:783). **Unsound or underspecified rule.** The accepted types include `f32`, small integers, and `bool`, but C requires default argument promotions in the variadic portion; QBE also needs the boundary between fixed and variadic arguments, not just the fact that a call is variadic. **Example:** `printf("%f", f32(1.5))` must pass a `double`; passing QBE `s` is wrong. **Smallest fix:** specify promotions and retain the fixed-argument boundary in IR, including after parameter expansion; specify QBE’s sub-word ABI types for narrow fixed parameters and results. See [C §6.5.2.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) and [QBE’s call specification](https://c9x.me/compile/doc/il.html).

6. **High — Record extension does not necessarily match a flattened C struct.** [Lines 436–444](/Users/kyle/projects/oberon/agents/vision.md:436). **False claim about existing code or a dependency.** The existing compiler starts extension fields after the base’s complete padded size, whereas a C struct listing all inherited fields followed by new fields can reuse the position occupied by the base’s tail padding. **Example:** `B = record { x: int; y: byte }` has size 16; adding `z: byte` through extension places `z` at offset 16, while C `{ int64_t x; uint8_t y; uint8_t z; }` places it at offset 9. **Smallest fix:** define an extended record’s C counterpart as a struct containing the complete base struct as its first member. The current behavior is explicit in [record layout](/Users/kyle/projects/oberon/src/sema/mod.rs:3779).

7. **High — The conversion policy gives incompatible meanings to “loss.”** [Lines 307–336](/Users/kyle/projects/oberon/agents/vision.md:307). **Unsound or underspecified rule.** Trapping on every loss would make ordinary `f64`→`f32` rounding trap, while the stated `int(2.7) = 2` deliberately loses information; NaN, infinity, signedness changes, and integer-to-float precision loss need distinct rules. **Example:** `var x = 0.1; var y = f32(x)` either traps or rounds depending on an unstated interpretation, and `int(0.0 / 0.0)` has no defined result. **Smallest fix:** add a conversion matrix defining rounding, truncation, finite/range checks, constant diagnostics, and runtime traps.

8. **High — Several advertised expressions cannot be generated by the grammar.** [Lines 318–319, 360, 375, 884–925](/Users/kyle/projects/oberon/agents/vision.md:913). **Contradiction within the document.** Call arguments are expressions, but anonymous type expressions are not expressions; conversions must start from a `designator`, which starts with a qualified identifier. **Examples:** `[]byte(greeting)`, `new([]int, 100)`, and `size_of([4]int)` fail; the promised parenthesized conversion `([]byte)(greeting)` also fails because a parenthesized primary cannot take a call selector. **Smallest fix:** add explicit conversion and type-operand builtin productions, and make the examples use their chosen spelling.

9. **High — The `errno` declaration is not a usable binding on the named platforms.** [Line 638; lines 800–803](/Users/kyle/projects/oberon/agents/vision.md:638). **Contradiction within the document.** The example declares `errno` as an ordinary external variable while the interface expressly excludes thread-local variables. macOS exposes it through `__error()` and glibc through `__errno_location()`; an ordinary data-symbol reference does not implement either contract. **Example:** reading the declared `errno` cannot reliably retrieve the current thread’s error value. **Smallest fix:** replace it with an accessor binding labeled for a particular platform, or a small portable C shim. Sources: [Apple’s header](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/errno.h), [glibc’s header](https://raw.githubusercontent.com/bminor/glibc/master/stdlib/errno.h).

10. **High — The fork’s relationship to the repository’s purpose is undecided.** [Lines 8–29, 977–993](/Users/kyle/projects/oberon/agents/vision.md:8). **Scope risk.** Replacing the language and translating away its corpus abandons AGENTS.md’s goal of implementing complete Oberon-07; creating a separate fork can preserve that goal for Oberon, but introduces maintenance and validation responsibilities the document never assigns. **Example:** after translating an Oberon rejection test into valid Puck, it no longer checks Oberon conformance. **Smallest fix:** explicitly choose a separate project retaining an upstream Oberon baseline, or coexistence with separate language tests and shared components, and state how fixes move between them.

11. **Medium — A foreign slice is not “as safe as its count.”** [Lines 420, 758–777](/Users/kyle/projects/oberon/agents/vision.md:758). **Unsound or underspecified rule.** A correct count does not establish allocation success, alignment, lifetime, or ownership, and bounds checks cannot prevent use after `free`. **Example:** the shown `malloc` may return nil, or `buf[0]` may be used after `free(raw)` while still passing its index check. **Smallest fix:** identify `slice` over foreign memory and unchecked pointer conversions as programmer-checked operations, list their validity obligations, and limit “pointers never dangle” to the managed subset; define negative-length and allocation-size-overflow checks too.

12. **Medium — Portable bindings have no specified platform-selection mechanism.** [Lines 624–627, 700–725, 800–805, 856–857](/Users/kyle/projects/oberon/agents/vision.md:700). **Scope risk.** Eight-byte pointers establish a 64-bit target assumption, but do not establish LP64 or a universal `time_t`/`struct tm` contract; alignment alone cannot establish C layout compatibility. The `Tm` example does match the checked LP64 macOS and glibc layouts, but the document names neither that boundary nor how one module chooses platform-dependent symbols. **Example:** an errno accessor needs `__error` on macOS and `__errno_location` on glibc, and both declarations cannot be selected by the language. **Smallest fix:** name the supported ABI/libc combinations and choose externally selected platform modules or C shims; document how shim objects enter the link. The current [driver](/Users/kyle/projects/oberon/src/driver.rs:64) does not accept arbitrary companion C sources. Layout sources: [Apple](https://raw.githubusercontent.com/apple-oss-distributions/Libc/main/include/_time.h), [glibc](https://raw.githubusercontent.com/bminor/glibc/master/time/bits/types/struct_tm.h).

13. **Medium — Type-switch narrowing is undefined for grammar-permitted subjects and labels.** [Lines 455–476, 562–565, 901–904](/Users/kyle/projects/oberon/agents/vision.md:455). **Unsound or underspecified rule.** An expression such as `MakeShape()` has no variable to retype, and `case Circle, Rect:` supplies no single narrowed type; overlapping base/derived labels also need a selection rule. **Example:** `switch s { case Circle, Rect: Out.Real(s.radius, 0) }` cannot justify access to `radius`. **Smallest fix:** initially require a stable variable subject and one type label per arm, and specify overlap precedence or rejection. Explicitly record that unmatched value switches now skip: Report §9.5 leaves the no-match result unstated, while this compiler traps for value `CASE` and skips unmatched type `CASE`.

14. **Medium — The two cycle rules disagree and exclude useful finite layouts.** [Lines 216–218, 946–947](/Users/kyle/projects/oberon/agents/vision.md:216). **Contradiction within the document.** The language allows cycles through pointers or procedure types, but the implementation summary mentions only pointers; slices also have fixed-size descriptors yet do not break a cycle under either wording. **Example:** `type Tree = record { children: []Tree }` is rejected despite a finite record layout. **Smallest fix:** define cycle legality through inline storage dependencies, explicitly naming pointers, slices, and procedure values as indirections; distinguish illegal alias/constant cycles from legal recursive type graphs. `string` is a fixed leaf type, so it needs no recursive exception.

15. **Medium — The ABI restrictions are presented as necessities when several are choices.** [Lines 675–680, 800, 957–961](/Users/kyle/projects/oberon/agents/vision.md:675). **False claim about existing code or a dependency.** QBE already implements C aggregate argument and return classification, including returning suitable small structs in registers; an explicit hidden out-pointer for every string/slice result is Puck’s chosen convention. “No hidden arguments” is also insufficient to prove ABI equivalence, since structured value parameters are passed by address. **Example:** a C `{ pointer, int64_t length }` result can return in two registers on AMD64 SysV, unlike the proposed Puck result. **Smallest fix:** describe the restrictions as an initial implementation boundary and distinguish pointer-plus-count parameters from C aggregate parameters/results. See [QBE’s ABI description](https://c9x.me/compile/doc/abi.html).

16. **Medium — Rebinding the existing string runtime preserves the wrong NUL behavior.** [Lines 809–832, 969–971](/Users/kyle/projects/oberon/agents/vision.md:809). **False claim about existing code or a dependency.** `oberon_lib_out_string` receives a pointer and length, but [stops at the first NUL](/Users/kyle/projects/oberon/runtime/standard.c:14); merely declaring that function with a Puck `string` parameter does not implement length-delimited string output. **Example:** `Out.String("a\0b")` emits only `a`. **Smallest fix:** include a semantic audit of text I/O and file encodings in the runtime migration, and explicitly define embedded-NUL behavior for `cstring(s)`—appending a terminator does not stop C from observing only the prefix.

17. **Medium — “Overflow wraps” is not an accurate blanket description of the current compiler.** [Lines 126–127](/Users/kyle/projects/oberon/agents/vision.md:126). **False claim about existing code or a dependency.** Ordinary generated integer addition, subtraction, and multiplication wrap, but `ABS(MIN(INTEGER))` deliberately traps, and signed division overflow is not normalized across targets. **Example:** `MIN(INTEGER) DIV -1` reaches machine division; the vendored AMD64 backend emits `idiv`, which faults for that case. **Smallest fix:** specify overflow behavior by operation and mark any stronger wrap guarantee as new implementation work, including division/remainder edge cases.

18. **Medium — Exact constant arithmetic is new work, not something that stays.** [Lines 132, 255](/Users/kyle/projects/oberon/agents/vision.md:132). **False claim about existing code or a dependency.** Constants currently use checked `i64` operations and `f64` arithmetic rounded at every operation, rather than arbitrary-precision exact arithmetic. **Example:** `const X = (9223372036854775807 + 1) - 1` fails at the intermediate addition today despite its representable final value. **Smallest fix:** either promise bounded constant evaluation explicitly or schedule a new exact constant representation and its conversion rules. Evidence: [constant evaluation](/Users/kyle/projects/oberon/src/sema/constant.rs:29).

19. **Medium — Sized integers lack a complete bit-operation contract.** [Lines 189–198, 328, 332–336](/Users/kyle/projects/oberon/agents/vision.md:189). **Unsound or underspecified rule.** Integer `and`/`or`/xor/mask operations are absent, while using `set` requires conversions whose signedness and width behavior are unspecified; `set(i32Value)` cannot simply reinterpret an unchanged 32-bit representation as a 64-bit value. Negative and oversized shift counts are also undefined, and QBE masks counts rather than supplying language checks. **Example:** `u8(1) << 8` could produce zero, trap, or reflect a wider intermediate; a `u32` mask currently needs a route such as `u32(u64(set(u64(x)) * set(u64(mask))))`. **Smallest fix:** document that route or add integer bit operators, restrict free set reinterpretation to equal-width types, and define shift domains and result truncation. Also state explicitly that integer `/` remains illegal and requires `div`.

20. **Medium — The newline rule makes ordinary multiline calls and sets impossible.** [Lines 155–160, 915, 925](/Users/kyle/projects/oberon/agents/vision.md:155). **Contradiction within the document.** A final argument or set element followed by a newline needs a comma to prevent termination, but only composite literals permit a trailing comma. **Example:**

    ```puck
    Out.Int(
        n,
        0,
    )
    ```

    The comma avoids newline termination but violates the call grammar; deleting it introduces termination before `)`. **Smallest fix:** permit trailing commas in calls and set literals, and make separator consumption explicit in the grammar or its conventions.

21. **Medium — The C examples silently introduce discarded function results.** [Lines 635–647, 793; “Everything else stays” at line 28](/Users/kyle/projects/oberon/agents/vision.md:635). **Unsound or underspecified rule.** `puts` and `printf` return `i32`, but their results are ignored; the existing compiler explicitly rejects calling a function as a statement. **Example:** `puts(home)` in `Env.main` requires a changed semantic rule, although the grammar can parse it. **Smallest fix:** expressly permit discarded results, or introduce and demonstrate an explicit discard operation.

22. **Medium — `copy` does not specify the string/buffer boundary.** [Lines 340–345, 380–381](/Users/kyle/projects/oberon/agents/vision.md:380). **Unsound or underspecified rule.** “Copies elements” does not say whether strings are permitted as sources, whether only matching element types are accepted, or whether overlapping views behave like `memmove`; immutable strings must never be destinations. **Example:** `copy(bytes, "abc")` and `copy(a[1:], a[:len(a)-1])` have no complete stated contract. **Smallest fix:** define accepted source/destination types, overlap behavior, and any return value; explicitly allow or reject string-to-byte copying. Specify length-sensitive unsigned-byte lexicographic string comparison so the current NUL-sensitive comparator cannot accidentally be reused.

23. **Medium — The recommended string-building pattern is quadratic.** [Lines 342, 348–354, 386–399](/Users/kyle/projects/oberon/agents/vision.md:348). **Hidden cost.** Each `out += p` allocates and recopies the accumulated prefix, so joining equal-sized pieces copies a quadratic total number of bytes and puts corresponding pressure on the collector. **Example:** joining *n* one-byte strings copies roughly *n(n+1)/2* bytes before accounting for separators. **Smallest fix:** label the example’s complexity and include a linear `Join` or builder using one allocation; define the byte-copy/string construction primitives needed to implement it.

24. **Medium — The library scope leaves common programs choosing duplication or unchecked C interfaces.** [Lines 807–842](/Users/kyle/projects/oberon/agents/vision.md:807). **Hidden cost.** Slices and `copy` do not provide hash tables, typed sorting, or formatting into strings, and no-generics/no-closures makes reusable implementations more expensive; naming `Utf8` supplies no iteration or invalid-input contract. **Example:** counting words needs a string-keyed map, sorting records with caller-specific ordering needs comparator context, and `for x in "é"` visits two bytes rather than one code point. **Smallest fix:** list the minimum library APIs or explicitly assign these costs to applications, including a concrete UTF-8 decoder API and malformed-input policy.

25. **Medium — The sequence buys incremental risk reduction by translating substantial tests twice.** [Lines 983–997](/Users/kyle/projects/oberon/agents/vision.md:983). **Hidden cost.** There are **251 fixture roots**—90 successful programs, 101 compile failures, 60 runtime failures—across **292 `.Mod` files**, plus generated tests in the Rust harness and six library modules. A textual inventory finds **55 roots/61 modules** directly mentioning open arrays, `CHAR`, or `Strings`, and **91 roots/105 modules** mentioning arrays or characters more broadly, putting a reasonable second-pass review estimate around **22–36% of fixture roots**, rather than every translation being final in step 1. **Example:** open-array mutability, string termination, and character-conversion tests must change again when slices and strings arrive; several negative tests must change category. **Smallest fix:** state that the order minimizes integration risk rather than rework, budget the second migration, and replace “step 5 is the smallest” with an ABI validation milestone.

26. **Low — `rune` cannot both alias all `i32` values and guarantee a Unicode scalar value.** [Lines 286, 300–303](/Users/kyle/projects/oberon/agents/vision.md:286). **Contradiction within the document.** An exact alias accepts negative integers, surrogate values, and values above the Unicode maximum. **Example:** `var r: rune = -1` is permitted by the stated constant compatibility rule. **Smallest fix:** call `rune` an integer conventionally holding a Unicode scalar, leaving validation to decoding/construction APIs.

27. **Low — Two arguments for removing Oberon rules misdescribe the existing language and corpus.** [Lines 210–214, 558–560](/Users/kyle/projects/oberon/agents/vision.md:210). **False claim about existing code or a dependency.** Oberon does not require every pointer’s base record to be separately named and declared afterward: the Report permits inline record bases and allows, rather than requires, forward references. `REPEAT` and `WHILE … ELSIF` also have concrete repository users. **Examples:** `POINTER TO RECORD x: INTEGER END`; [Repeat.Mod](/Users/kyle/projects/oberon/tests/corpus/Repeat.Mod:6) and [While.Mod](/Users/kyle/projects/oberon/tests/corpus/While.Mod:15). **Smallest fix:** narrow the pointer claim to recursive forward references and describe the loop removal as a simplification with migration costs.

28. **Low — “Reads it without a manual” overstates familiarity, and the precedence claim is false.** [Lines 103–104, 183–198](/Users/kyle/projects/oberon/agents/vision.md:103). **Hidden cost.** Both Go and Odin readers expect `:=` to declare and `=` to assign, and both use symbolic Boolean operators; Go readers additionally read `^` as xor/complement and expect `func`, while Odin readers recognize pointer `^` and `proc` but expect declaration syntax such as `Area :: proc`. **Examples:** `best := s` can be mistaken for a new binding; `not x in s` parses as `(not x) in s`, not negated membership; `1 << 2 + 1` groups differently from C because these are Go-like shift precedences. **Smallest fix:** replace the universal readability claim with a short migration table and document these exact parses. Sources: [Go specification](https://go.dev/ref/spec), [Odin overview](https://odin-lang.org/docs/overview/).

**Claims checked and found correct:**

- `Fill` may modify slice elements: the document explicitly permits that without allowing reassignment of the parameter.
- Fresh procedure-type identity can coexist with signature-based value compatibility; the current compiler implements both.
- Under the stated recursive compatibility definition, `proc(s: string)` is **not** foreign-compatible; the direct foreign-parameter expansion exception does not automatically apply to callbacks. Those statements need not contradict each other.
- Open arrays currently pass an address plus lengths; record `var` parameters carry dynamic descriptors.
- QBE supports variadic calls, and the compiler already emits terminated static string data.
- `else:` in `switch` and `else` in `if` match the grammar; postfix `^` is deliberately included in newline termination.
- Adjacent `0..<n` and `1..=10` are lexable; the existing numeric scanner already preserves `..` instead of consuming its first dot as a decimal point.
- Views into immutable static string data have no lifetime problem.
- The shown `Tm` fields match the checked LP64 macOS and glibc layouts; this does not establish universal portability.
- With the existing `cc` link path, `foreign "c"` ordinarily adds a redundant `-lc`; the string selects a library, not a calling convention.

**Revise first.** The three deciding findings are descriptor lookup for arbitrary record pointers, escapes through parameter/subobject storage, and the missing slice/pointer compatibility rules. They determine whether the language is memory-safe and whether its introductory examples have a coherent type derivation; implementation should not begin by translating the corpus before those contracts are settled.
